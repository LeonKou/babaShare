02 / 协作，有清晰的边界

同一个工作区，
各自合适的位置。

让需要动手的人编辑，让需要了解的人查看。把文件、成员和访问控制放在同一个地方。

三种角色，权限清楚

权限实时生效，MCP 同样遵循账号权限。工作区协作设置不会让查看者获得编辑能力。

管理员管理账号与全部工作区
编辑者在授权范围内创建、修改
查看者只读查看有权访问的内容

分享出去，也能收回来

目录分享支持限时或永久有效，也支持随时撤销。分享链接本身就是访问凭据，请只交给合适的人。

有期限的讨论，不必留下无限期的入口。

页面之外，资源一起到位

多级目录、批量上传、搜索和在线 UTF-8 编辑，照顾完整原型的日常管理。同名冲突可覆盖、保留两份或取消。

为静态原型而设计

目录入口优先匹配 index.html，其次 home.html。受控沙箱预览支持脚本，但部分联网、存储和窗口能力受限。

04 / 轻装部署

一个服务，
就能开始协作。

Python 3.12+ 标准库、SQLite 和原生前端。无需 pip / npm 安装，无需编译；页面、API、MCP 与预览共用一个 HTTP 端口。

从项目根目录开始

先获取仓库代码，再按实际环境选择启动方式。仓库当前为私有，访问代码和文档需要相应权限。

阅读完整部署手册 ↗

在受控网络完成首位管理员初始化。公网部署前配置 HTTPS 与访问策略；备份时保留整个数据根。

python --version
python server.py

需要 Python 3.12+（含 sqlite3）。Linux 可使用 python3。前台命令不代替系统服务。

docker compose config
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=100

需要 Docker Compose。持久化整个数据根，不仅是 filedb 或单个数据库文件。

启动后访问 http://127.0.0.1:8080/baba-share/

05 / 开始之前

你可能还想知道。

把边界讲清楚，才好放心放进工作流。

这里可以直接上传或在线试用吗？

这里是静态产品官网。上方窗口仅使用本地演示数据，没有上传、登录或真实分享服务。实际使用需要先部署 babaShare，并在自己的实例上创建账号。

能保留完整原型的目录结构吗？

可以管理多级目录并上传 HTML、CSS、JavaScript 和图片，请保留相对资源引用。根绝对路径不会自动改写；保留两份同名文件也不会改写 HTML 引用。

可以托管带后端的应用吗？

产品面向静态 HTML 原型，上传的 PHP、Python 或 Node.js 服务端脚本不会执行。依赖联网 API、登录态、持久存储、表单或弹窗的原型，可能受预览沙箱限制。

编辑者和查看者有什么区别？

编辑者可创建工作区，并在工作区及文件归属权限范围内修改内容；查看者始终只读。成员协作设置不会越过账号角色边界，MCP 也继承这些实时权限。

数据放在哪里？如何备份？

数据保存在你指定的本地数据根，包括 SQLite、上传文件和存在时的 MCP 主密钥。优先停止服务后成套备份整个根目录，不要只拷贝运行中的数据库主文件。

为什么 GitHub 链接需要授权？

当前仓库为私有，查看代码、部署手册和 MCP 文档需要对应的 GitHub 仓库权限。本页不承诺开放下载，也不声明开源许可证。
